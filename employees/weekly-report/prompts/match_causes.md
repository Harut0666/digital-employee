# 步骤：从纪要匹配异常原因

本步骤为程序检出的每条异常，在周会纪要里找到原因，并把纪要中数据里有的指标的判断抽出来。结果通过 `submit_result` 工具提交，不要在对话里直接回答。

## 输入

本步骤收到的消息是一份 JSON，字段如下：

| 字段 | 内容 |
|---|---|
| `period` | 统计周期，`year` 和 `week` |
| `anomalies` | 程序检出的异常清单。每条有 `id`（如 `region:华南`、`store:SH02`）、`level`（区域或门店）、`name`、`region`、`storeType`（门店才有）、`wow`（环比）、`revenueCents`、`prevRevenueCents`、`baseWeekHasMissingDays` |
| `company`、`regions`、`stores`、`categories` | 事实，供你判断说法针对的对象是否存在、方向对不对，不要抄数 |
| `minutes` | 解析后的纪要，每份有 `week`（识别出的周次，可能为空）、`title`、`paragraphs`（每段有 `id`、`section`、`text`） |
| `feedback` | 解读后的退回意见清单（`kind` 为 `cause` 的条目与本步骤有关）；首次执行时为空 |

如果消息里还有 `corrections`，那是质检指出的具体问题，必须逐条改正。

## 一、匹配原因

对 `anomalies` 里的**每一条**异常，输出恰好一条原因，`anomalyId` 取自该异常的 `id`，不得遗漏、不得多出。

按以下顺序找原因，找到即停：

1. **门店层级**：本周纪要里有针对这家门店的专门说法，`level` 记为 `store`。区域异常没有门店层级，直接从区域找起。
2. **店型层级**：纪要对这家门店所属店型整体作了说明（如“商场店、街边店、社区店普遍回落”“写字楼店明显回升”），`level` 记为 `store_type`，原因末尾加“（店型整体原因）”。
3. **区域层级**：纪要对这家门店所属区域整体作了说明（如活动结束后回落），`level` 记为 `region`，原因末尾加“（区域整体原因）”。区域异常本身的原因也记为 `region`，不加该标注。
4. **全公司层级**：纪要对整体情况的说明，`level` 记为 `company`。
5. **都没有**：`cause` 只写“原因待核实”，`level` 记为 `unknown`，不写 `sourceWeek` 和 `quote`，不得推测。

规则：

- 只用**统计周期那一周**的纪要解释原因（`minutes` 里 `week` 与 `period` 相同的那份）。其他周的纪要不用于解释原因，也不要拿来凑数。没有本周纪要时，全部写“原因待核实”。
- `sourceWeek` 写所用纪要的 `year` 和 `week`，`quote` 写原文摘录：必须从该份纪要某一段的 `text` 里**逐字复制一段连续文字**，不改字、不增删标点、不拼接多段。一条原因最多一段摘录，选最短而足以支撑原因的那一句。
- `cause` 只复述摘录里已有的内容，不添加摘录里没有的因果，不用“可能”“估计”“应该”。
- 原因的方向要与异常一致：异常是下滑，原因必须是能解释下滑的说法；纪要里与方向相反的说法（如带动增长的促销）不能用来解释下滑。
- 同一件事影响多家门店时，每家门店各写一条，都要有摘录。
- 异常的 `baseWeekHasMissingDays` 为真时，原因里不必提，由撰写步骤附注。
- 门店的停业：纪要写明该店在本周某几天停业的，就是该门店下滑的原因，`level` 为 `store`。

## 二、抽取可核验说法

把纪要中**针对数据里有的指标**所作的判断抽成 `claims`，供程序判定是否构成纪要矛盾。只抽本周纪要里的说法。

- 目前只抽实收环比方面的说法：纪要对某个对象（全公司、区域、门店、品类）说“销售持平”“基本持平”“上升”“下降”“下滑两成”之类。`metric` 固定为 `wow`。
- `subject.level` 和 `subject.key`：全公司写 `company` 加 `company`；区域写区域名；门店写门店编码（从 `stores` 里按店名找）；品类写品类名。对象在事实里找不到的，不抽。
- `direction`：持平写 `flat`，上升写 `up`，下降写 `down`。
- `magnitude`：纪要给出幅度才写，按小数写（“两成”写 0.2，“约七成”写 0.7，“下降 5%”写 0.05）；没给幅度就不写。
- `quote` 同样逐字复制，`sourceWeek` 写所在纪要的周。
- 客流、杯量、口感、库存、进度之类数据里没有的说法，**一律不抽**。不要自己判断说法对不对，只抽取，判定由程序做。
- 没有可抽取的说法，`claims` 提交空数组。

## 输出

调用 `submit_result` 提交一个 JSON 对象，只含 `causes` 和 `claims` 两个字段，结构符合本步骤的输出 Schema。不要提交别的字段，不要在 `cause` 里写数字计算。
