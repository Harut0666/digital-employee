# 步骤：解读退回意见

本步骤只在审核人退回周报、任务重做时有实际工作：把退回意见拆成逐条意见，指明每条要改哪个章节，供后面的叙述步骤逐条响应。结果通过 `submit_result` 工具提交，不要在对话里直接回答。

## 输入

本步骤收到的消息是一份 JSON，字段如下：

| 字段 | 内容 |
|---|---|
| `feedback` | 审核人的退回意见：`comment`（自由文本）和可选的 `sections`（审核人勾选的章节标签）。首次执行时没有这个字段或为空 |
| `previousDraft` | 被退回的上一版周报草稿（章节、段落、要点）。首次执行时没有 |
| `sections` | 全部章节，每个有 `id` 和 `heading` |

退回意见也可能出现在 `corrections` 里。无论哪种形式，凡是审核人的意见都要处理。

## 要做什么

1. **没有任何退回意见**（首次执行）：直接提交 `{ "items": [], "needsHuman": false }`，不要编造意见。
2. **有退回意见**：把它拆成互相独立的条目，一条意见一个条目，保持审核人的原意，不扩写、不合并不相干的意见。每个条目：
   - `id`：F1、F2……按出现顺序；
   - `comment`：该条意见的原话或忠实转述；
   - `sections`：要改动的章节 `id`。审核人勾选了章节的，以勾选为准；没勾选的，对照 `previousDraft` 判断意见针对哪些章节。确实对应不到章节的，给空数组；
   - `kind`：
     - `narrative`：要改叙述、措辞、详略、结构；
     - `cause`：要改异常原因，或原因的写法、出处；
     - `calculation_basis`：要求更换计算口径，如“毛利按含税算”“实收不扣折扣”“把停业日算进去”；
     - `unclear`：无法判断想要什么；
   - `action`：打算怎么改，一句话，不写数字。
3. **超范围意见回到待审核**写在顶层，不写在条目里：
   - `needsHuman`：只要有一条是 `calculation_basis`，或有一条与《周报格式要求》冲突（如要求写同比、客单价，或要求超出 3 页）而无法照办，就为 `true`：这条意见超出自动处理范围，任务回到待审核，原交付物和版本保持不变；否则为 `false`；
   - `needsHumanReason`：`needsHuman` 为 `true` 时必填，一句话说明是哪条意见、为什么不能自动处理，给审核人看；`needsHuman` 为 `false` 时省略。

## 注意

- 事实和计算口径由程序决定，意见要求换口径的，不要设法用叙述绕过，如实标 `calculation_basis`，并把顶层 `needsHuman` 置为 `true`，让任务回到待审核。
- 不要判断意见是否合理，也不要替审核人补充意见。

## 输出

调用 `submit_result` 提交一个 JSON 对象，含 `items`、`needsHuman`，需要让任务回到待审核时再加 `needsHumanReason`，结构符合本步骤的输出 Schema。
