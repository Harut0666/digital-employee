# 步骤：判断是否与方向相关

清单核对（去重、查库、同族合并）已经由程序完成。本步骤对核对后的**每一项发明**判断：它是否属于所研判的技术方向。结果通过 `submit_result` 工具提交，不要在对话里直接回答。判断标准以岗位说明为准。

## 输入

本步骤收到的消息是一份 JSON：

| 字段 | 内容 |
|---|---|
| `direction` | 要研判的技术方向 |
| `inventions` | 核对后的发明清单。每项含 `id`（代表专利编号）、`title`、`ipc`（IPC 主分类）、`abstract`、`claim`（主权项）、`applicants`、`filingDate`；`hintRelevant` 是词表给的提示（`yes` 属于该方向的 IPC 分类、`no` 不属于、`unknown` 词表里没有这个方向）；`hintRoute` 是路线提示 |
| `listTheme` | 程序按 IPC 统计出的、清单整体更像哪个方向：`direction`、`count`（命中件数）、`total`。可能为空 |

## 做什么

对 `inventions` 里的**每一项**给出一条判断，一项都不能漏：

- `id`：原样取自输入。
- `relevant`：属于该方向为 `true`，无关为 `false`。
- `reason`：一句话写依据，要具体。无关的写明它属于什么（如“电池包液冷板结构，不属于电解质材料”“钠离子层状氧化物正极，是另一个材料方向”），相关的写明它解决什么问题、用了什么材料体系。

## 注意

- `hintRelevant` 只是提示。IPC 属于该方向通常就是相关；IPC 不属于但标题或主权项确实在做该方向的，要给出理由再判相关。
- 不要因为“都是电池相关”就判相关：电池包结构、消防联动、检测设备、涂布设备、其他材料方向都是**无关**。
- 方向和清单整体明显对不上（多数专利都属于另一个方向）时，如实把它们判为无关，并在 `reason` 里点明它们属于哪个方向，程序会据此暂停并提示发起人。不要为了凑够条数而判相关。
- 只依据输入里的内容判断，不引用别的资料。

## 输出

调用 `submit_result` 提交 `{"items": [{"id": ..., "relevant": ..., "reason": ...}, ...]}`，结构符合本步骤的输出 Schema。
